## 1. Библиотека инструментов (`screen_15_tool_library.html`)

Документация была обновлена под актуальные фронтенд/бэкенд файлы и логику, в которой фактический учет остатков ведется через поле `ToolTypes.count`. Таблица `Tools` осталась только для устаревших сценариев и больше не является источником правды для библиотеки.

### 1.1 Источник данных для таблицы

- __Frontend__: `screen_15_tool_library.html` подключает `../scripts/tool_library/createTableToolLibrary.js`. Функция `loadToolLibraryTable` дергает `fetchToolLibraryData(device_number)` и подгружает данные в BootstrapTable.
- __Backend__: `server/API/backend/endpoints/all_tools.py` → `GET /get_groups_from_db?device_number=X`.

```python
def get_groups_from_db(device_number: int, db: Session):
    tool_type_crud = EngineToolTypes()
    e_group = EngineGroup()

    all_tool_types = tool_type_crud.get_all_tool_types()
    for tool in all_tool_types:
        count = tool.count if tool.count > 0 else '-'
        immediate_group_obj = e_group.get_group_by_id(tool.groups_id)
        ...
        tool_list.append({"group": immediate_group, "name": tool.name,
                          "description": tool.description, "sum": count})
```

__Что отображается__:
- Каждая строка соответствует записи `ToolTypes`.
- Значение `sum` рассчитывается напрямую из `ToolTypes.count` (никаких выборок по `Tools`/`Tools_has_Device`).
- Состав групп собирается по `Group` → `parent_group`, чтобы показать дерево.

### 1.2 Добавление инструмента вручную

- __Frontend__: кнопка «Добавить инструмент» ведёт на `screen_16_add_tool.html`. Скрипт `collectDataAndSend` собирает `group_id`, `tool_name`, `description`, `count` (опционально) и POST'ит JSON на `../backend/create_tools`.
- __Backend__: `server/API/backend/endpoints/all_tools.py` → `POST /create_tools`.

```python
def create_tools(data: ToolsCreate, db: Session):
    group = group_crud.get_group_by_id(data.group_id)
    existing_tool = tool_type_crud.find_tool_types_by_name(data.tool_name)
    if not existing_tool:
        new_tt_id = max(tool_type_crud.get_all_ids(), default=0) + 1
        tool_type_crud.add_tool_type(
            tool_type_id=new_tt_id,
            name=data.tool_name,
            description=data.description,
            count=data.count,
            img=data.img,
            groups_id=data.group_id,
        )
    else:
        tool_type = existing_tool[0]
        tool_type_crud.update_tool_type(
            id=tool_type.id,
            count=tool_type.count + data.count,
            ...
        )
```

__Важно__:
- Новые инструментальные позиции = новые или обновлённые строки в `ToolTypes`.
- `Tools`, `Tools_has_Device` и `ToolLocation` не затрагиваются; инвентарные номера из UI сохраняются только в теле запроса и не попадают в БД.
- Чтобы уменьшить количество, сейчас используется тот же endpoint (отправляется отрицательный `count`). Отдельного метода «удалить инструмент» нет.

### 1.3 Импорт XLSX

- __Frontend__: форма загрузки на `screen_15` дергает `doImportTools` (`server/frontend/scripts/tool_library/toolsImport.js`), который отправляет `FormData` на `../backend/upload` плюс флаг `use_count`.
- __Backend__: `server/API/backend/endpoints/tool_library.py` → `upload_xlsx`.

```python
records = parse_excel(...)

for record in records:
```

__Итог__: импорт формирует/обновляет типы и увеличивает `ToolTypes.count`. Код, создающий физические `Tools`, закомментирован и не выполняется.

### 1.4 Модификация записей

- Визуальные кнопки «✏️/❌» пока не привязаны к API.
- Все изменения проводятся через повторные вызовы `/create_tools` или через XLSX-импорт.
- Удаление/уменьшение остатков должно аккуратно изменять `count`, иначе расходование (см. раздел 3) отнимет единицы, уходя в отрицательные значения.

## 2. Массовая загрузка (`screen_2_mass_load.html`)

### 2.1 Выбор доступных типов

```python
@mass_load_router.get("/mass_load_tools")
def export_tools(device_number: int):
    all_tool_types = e_tool_types.get_all_tool_types()
    for tool_type in all_tool_types:
        count = tool_type.count
        loads = e_load.find_by_tools_id(tool_type.id)
        if loads:
            count -= len(loads)
        tool_type_list.append({"id": tool_type.id,
                               "name": tool_type.name,
                               "description": tool_type.description or "",
                               "sum": count})
```

- Фронтенд получает список типов с учётом уже созданных `Load` (каждая активная загрузка уменьшает доступное количество). Никакого обхода `Tools` нет.
- Ячейки (`cells_map/{device_number}`) также читают `cell.tools_id` как id типа инструмента и показывают статус через `Status.stype`.

### 2.2 Сохранение сценария (`POST /mass_load_tools/{device_number}`)

```python
def save_mass_load(..., mass_load: MassLoadCreate):
    validate_user()
    device = e_device.get_device_by_number(device_number)
    mass_load_id = max(e_mass_load.get_all_ids(), default=0) + 1
    e_mass_load.add_mass_load(...)
    for story in mass_load.operation.values():
        tool_type = e_tool_types.get_tool_type_by_id(story.tool)
        cell = e_cells.get_cell_by_id(int(story.cell))
        e_cells.update_cell(...,
            groups_id=tool_type.groups_id,
            tools_id=tool_type.id,
            status_id=mass_load_status.id)
        e_load.add_load(..., tools_id=tool_type.id, cell_id=cell.id, plan_id=story.plan)
        e_load_operation.add_operation(..., load_tools_id=tool_type.id)
        e_history.add_history(..., tools_id=tool_type.id)
```

- `story.tool` уже содержит id `ToolTypes`, поэтому дополнительных поисков по имени не требуется.
- Загрузка работает только с типами: нет создания `Tools` и нет связей `Tools_has_Device`.
- Отказоустойчивость: при исключении выполняется ручной откат (`Load`, `LoadOperations`, `History`, `Cells`, `MassLoad`).

### 2.3 Что появляется в БД

- `MassLoad`, `Load`, `LoadOperations`, `History`, `History_has_Device`, `CellHasDevice`.
- `Cell.tools_id` = id типа, `Cell.status_id` = `mass_load_init` на момент объявления.
- Доступность = `ToolTypes.count – количество активных записей в Load` (см. 2.1).

## 3. Выдача / массовая выгрузка

Единственная актуальная автоматизированная выдача реализована через экран `screen_3_mass_drop` и endpoint `/mass_drop_tools/{device_number}`.

### 3.1 Фронтенд

- Скрипт `server/frontend/scripts/massdrop/saveHistoryAsMassDrop.js` формирует `window.appData.story` и отправляет JSON вида:

```json
{
  "operation": {
    "1": {"cell": "12", "tool": "Сверло 0.5", "plan": "None"},
    ...
  }
}
```

### 3.2 Сервер (`server/API/backend/endpoints/mass_drop.py`)

```python
def save_mass_drop(device_number: int, mass_drop: MassDropCreate):
    validate_user()
    device = e_device.get_device_by_number(device_number)
    mass_drop_id = max(e_mass_drop.get_all_ids(), default=0) + 1
    e_mass_drop.add_task(...)
    for story in mass_drop.operation.values():
        tool_type = resolve_tool_type_by_name(story.tool)
        e_tool_types.update_tool_type(
            tool_type_id=tool_type.id,
            count=tool_type.count - 1,
            ...
        )
        tool_to_drop = find_free_tool_record(tool_type.id)
        cell = e_cells.get_cell_by_number(int(story.cell))
        e_tools_has_device.unlink_tool_from_device(tool_to_drop.id, device.id)
        e_cells.update_cell(..., groups_id=0, tools_id=0, status_id=0)
        e_drop.add_drop(..., tools_id=tool_to_drop.id, cell_id=cell.id)
        e_drop_operation.add_operation(..., tools_id=tool_to_drop.id)
```

- Основной остаток уменьшается через `ToolTypes.count - 1`.
- Поиск конкретной строки `Tools` всё ещё используется, чтобы связать выгрузку с историческими drop-записями. Эти строки считаются «виртуальными носителями», но не участвуют в библиотеке.
- Ячейка очищается (обнулённые `groups_id`, `tools_id`, `status_id`), после чего инструмент доступен для повторной загрузки.

### 3.3 Последствия

- `ToolTypes.count` ― единственный показатель свободного запаса.
- Возврат/списание проводится только через изменение `count`. Таблица `ToolLocation` не обновляется: статусы визуализируются через `Cell.status_id` и историю операций.

## 4. Основные таблицы и статус их использования

| Таблица | Где используется сейчас | Комментарий |
|---------|------------------------|-------------|
| `ToolTypes` (`server/DB/Models/ToolTypes.py`) | `/get_groups_from_db`, `/create_tools`, `/upload`, `/mass_load`, `/mass_drop` | Хранит тип, описание, `count`. Это источник правды для складских остатков. |
| `Group` | Все операции библиотеки и фильтрации | Формирует дерево групп и связи с `ToolTypes`. |
| `Cell` + `CellHasDevice` | `/cells_map`, `/mass_load`, `/mass_drop` | `Cell.tools_id` теперь содержит id типа инструмента, а не отдельный `Tools`. |
| `MassLoad`, `Load`, `LoadOperations`, `History` | `/mass_load_tools` | Фиксируют объявленные загрузки, статусы `mass_load_init`, связь с устройством и пользователем. |
| `MassDrop`, `Drop`, `DropOperations`, `History` | `/mass_drop_tools` | Отражают выдачу и уменьшают `ToolTypes.count`. |
| `Tools` | Только в `mass_drop.py` и наследованных CRUD | Используется как вспомогательный список для сопоставления drop/plan. Не пополняется библиотекой. |
| `ToolLocation` | Не используется | Код, который обновлял `ToolLocation.status_id`, не вызывается в актуальных сценариях. |

## Сводка текущего процесса

1. **Создание/импорт инструмента** → добавляется или обновляется строка в `ToolTypes`, `count` увеличивается.
2. **Масс-загрузка** → `Load/LoadOperations/History` резервируют ячейки, а `Cell.tools_id` ссылается на тип. Свободный остаток вычисляется как `ToolTypes.count - len(active Load)`.
3. **Масс-выгрузка / выдача** → `ToolTypes.count` уменьшается, ячейки очищаются, в историях появляются записи `Drop`.
4. **Таблицы `Tools` и `ToolLocation`** остаются для обратной совместимости и не участвуют в UI библиотеки инструментов; любые расчёты должны опираться на `ToolTypes`.
